# 회사홈페이지 (_앱_작업노하우.md)

## 1. 프로젝트 개요 및 기술 환경
- **역할:** YJ 스튜디오 공식 회사 홈페이지 및 스튜디오 통합 관제 본부(`/admin`)
- **기본 구성:** TanStack Start + React 19 + Tailwind CSS v4 + Recharts + Supabase
- **연동 주의사항 (`AGENTS.md`):**
  - Lovable과 연결된 저장소이므로 `supabase/migrations/`나 `drizzle/` 파일을 임의로 생성·수정하지 않는다.
  - DB 테이블 변경이 필요할 때는 Lovable 에디터 또는 Lovable MCP를 통해 반영한다.
  - 모든 비밀키(관리자 비밀번호, 타 앱 서비스 키, 텔레그램 봇 토큰, 구글 플레이 서비스 계정 등)는 절대 코드에 직접 적지 않고 서버 환경 변수와 `C:\dev\yj-apps\비밀키\회사홈페이지\`에 보관한다.

## 2. 통합 관제센터(`/admin`) 구조 및 2층 재활용 자산
- **관리자 인증 (`src/lib/admin-auth.ts`, `src/lib/admin-session.server.ts`):**
  - `꿈소반`·`대나무속풀이`에서 검증된 HMAC 서명 기반 `httpOnly` 쿠키 세션(`yj_admin`) 방식을 재활용한다.
  - 서버 환경 변수 `ADMIN_PASSWORD`가 설정되어야 로그인 가능하며, 5회 실패 시 60초 잠금이 걸린다.
- **블록식 앱 명세서 (`src/lib/studio-blocks/registry.ts`):**
  - 각 앱을 하나의 블록 객체(`StudioAppBlock`)로 정의한다.
  - 새 앱 추가 시 이 명세서에 블록을 추가하고, 원격 저장소 연결이 필요한 경우 환경 변수(`REMOTE_<APP_KEY>_URL`, `REMOTE_<APP_KEY>_SERVICE_KEY`)만 추가하면 관제센터 UI에 자동으로 나타난다.
- **원격 앱 브릿지 (`src/lib/studio-blocks/remote-bridge.server.ts`):**
  - 각 앱의 Supabase 저장소에 서버에서 직접 REST/SDK로 접속해 글 목록 조회·저장·발행·삭제를 수행한다.
  - 지원 테이블 규격:
    - `찻잔타로`, `꿈소반`: `guides` (`id, slug, title, description, body, published, updated_at`)
    - `대나무속풀이`: `stories` (`id, slug, title, description, body, published, updated_at`)
    - `울동네`: `welfare_posts` (`id, title, status, blog_draft_title, blog_draft_body, ...`)
- **긴급 알림 엔진 (`src/lib/alerts.server.ts`):**
  - 이메일(Resend 등) 및 텔레그램 봇 발송 인터페이스와 쿨타임(중복 경보 방지) 로직을 내장한다.
  - 환경 변수(`ALERT_EMAIL_TO`, `RESEND_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`)가 등록되면 즉시 실제 발송이 활성화된다.

## 3. 향후 작업 시 체크리스트
- 새 앱을 관제센터에 붙일 때: `registry.ts`에 블록 1개 추가 → 해당 앱의 `.env` 연결 키를 서버 환경 변수에 등록 → 필요 시 앱 내부에 텔레메트리(방문/AI 호출 보고) 3줄 추가.
- 디자인 원칙: 화이트 바탕(`#ffffff`) + 블루 포인트 + 정돈된 구분선·여백(구글 공개 표준 스타일)을 유지한다.
